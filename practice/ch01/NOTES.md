# NOTES.md — 第 01 章演練紀錄

## 做了什麼

- 建立 `FRICTION.md`：列出 5 個「每次都要重複提醒 Claude」的開發摩擦，各自對應 Skill／Subagent／Hook，每個附一句理由，最後用一張表總結三者分工。
  - Skill：commit 格式、PR 描述格式（知識／流程）
  - Subagent：安全與邊界案例審查（獨立 context 的專家）
  - Hook：禁改資料夾、改檔後自動 format（確定性強制）
- 檔案前面加了一段「判斷準則」三問，方便日後遇到新摩擦時快速分類。

## 驗證結果

- 本章只要求產出分析文件，**沒有建立任何 skill／agent／hook 檔案**，所以不需要用 `claude -p` 開新 session 觸發驗證。
- 已人工檢查：5 個摩擦齊全、每個都有「解法＋一句理由」、總結表涵蓋本質／觸發時機／強制力／適用內容四個面向。
- 未動到全域 `~/.claude/`，未建 GitHub repo、未 push。

## 和書上做法的差異

- 書上練習只要求「列摩擦＋對應機制＋總結表」；本版多加了：
  1. 開頭的「判斷準則」三問（把分類邏輯變成可重複使用的決策表）。
  2. 摩擦 1 註明「Skill 為主、Hook 為選配補強」，說明同一個摩擦可以軟硬兼施——Skill 負責寫對，Hook 負責兜底。
  3. 總結表多了「強制力」與「對應摩擦」兩欄，讓三者差異更好對照。
- 摩擦例子取自實際使用經驗（繁中 commit 格式、migrations 禁改、formatter 常被忘），而非書中的範例。
- 快速 demo 模式：未走 QA／審查流程。
