# PR 審查清單

依下列清單逐項審查目標檔案，每項標示 ✅ 通過 / ⚠️ 建議 / ❌ 必改，並附行號與修正建議。

## 1. 正確性
- 邏輯是否符合需求、邊界條件（空值、None、極值）是否處理
- 有無明顯 bug（錯誤比較、off-by-one、未使用的回傳值）

## 2. 安全性
- 有無硬編碼密碼、API key、token
- SQL 是否使用參數化查詢（禁止字串組合）
- 使用者輸入是否驗證

## 3. 錯誤處理
- 外部 I/O（檔案、網路、DB）是否有 try/except 且例外類型具體
- 錯誤訊息是否洩漏內部資訊

## 4. 可讀性與風格
- 命名是否表達意圖、函式是否過長（> 30 行）、巢狀是否過深（> 3 層）

## 5. 測試
- 是否有對應測試或冒煙測試

## 輸出格式

```
## PR 審查結果：<檔名>
| 類別 | 結果 | 說明（行號） |
|------|------|-------------|
...
**結論**：APPROVE / REQUEST CHANGES
```
