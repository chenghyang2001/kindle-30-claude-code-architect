# explain-error：錯誤訊息解讀

## 執行步驟

1. **定位**：從 stack trace 找出「最內層、屬於使用者程式碼」的那一幀（檔名＋行號），忽略框架／標準庫內部的幀。
2. **分類**：判斷錯誤類型（型別錯誤、未定義、空值存取、索引越界、匯入失敗、權限、編碼……）。
3. **推論根因**：說明「為什麼」會發生，不只是重述錯誤字面意思。資訊不足時，列出最可能的 1～3 個原因並排序。
4. **給修正**：提供可直接套用的修正程式碼片段。
5. **預防**：一句話說明以後怎麼避免同類錯誤。

## 輸出格式（必須照此標題）

```
## 🔴 錯誤摘要
<一句話說明發生什麼錯>

## 🔍 根本原因
<出錯位置（檔案:行號 / 函式）＋為什麼會發生>

## 🛠️ 修正步驟
1. ...
2. ...
（附修正後程式碼）

## 🛡️ 預防建議
<一句話>
```

## 注意

- 一律繁體中文；錯誤名稱、函式名保留原文。
- 不要捏造使用者沒提供的檔案內容；需要更多資訊時直接說明缺什麼。
